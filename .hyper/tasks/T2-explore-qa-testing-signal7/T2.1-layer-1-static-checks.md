## What

Extend the existing `scripts/run-signal-fixtures.sh` with three new validation functions that run deterministically (no LLM) against all skill SKILL.md files and fixture expectations.md files.

Three new checks:
- `check_verdict_encoding_parity`: parse each `SKILL.md` `## Output Contract` section, extract every fenced YAML block, validate it is a valid `signal_verdict` with keys `verdict`, `target`, `summary` and that `verdict` is one of the 5 legal values from `gates.md`.
- `check_output_contract_completeness`: for each phase skill, grep body text for verdict-indicating words (`return`, `redirect`, `awaiting`) and cross-reference against the `## Output Contract`. Flag any verdict mentioned in body but absent from contract, or vice versa. Skip narrative uses of those words that are clearly not verdict declarations.
- `check_fixture_expectation_parity`: parse each fixture's `expectations.md` expected-verdict YAML block and validate it matches one of the verdicts declared in the target skill's `## Output Contract`.

The runner must still pass all existing structural checks (frontmatter, enums, `<TODO>` sentinels, idempotency keys).

## Why

AC 1, AC 9 — Layer 1 catches doc-vs-contract drift without a model, runs in under 5 seconds, and can be executed on every commit. The three reviewer-flagged T1 regressions that were behavioral (compliance default, rework loop, campaign redirect) all had detectable doc-vs-contract symptoms that these checks would surface.

## Done when

- `./scripts/run-signal-fixtures.sh` exits 0 with all current fixtures and skills.
- The three new check functions print PASS/FAIL per check per fixture/skill.
- Intentionally breaking a contract (e.g., removing a verdict from Output Contract while body still references it) exits non-zero.
- Runner completes in under 5 seconds.

## Completion

- `scripts/run-signal-fixtures.sh` — 3 new functions + 4 helper functions + skill-scan loop:
  - `check_verdict_encoding_parity`: Extracts `## Output Contract` section from each `skills/*/SKILL.md`, parses every fenced YAML `signal_verdict` block, validates three required keys (`verdict`, `target`, `summary`) exist and `verdict` is one of the 5 legal values from `gates.md`.
  - `check_output_contract_completeness`: Cross-references `Allowed verdicts:` line (inside Output Contract section) against verdicts extracted from YAML examples; also scans body text for backtick-quoted verdict values not in the declared set.
  - `check_fixture_expectation_parity`: Parses `## Expected verdict` YAML block from each fixture's `expectations.md`, infers target skill from `## Trigger` text (via `signal-<name>` pattern), and validates the expected verdict is in that skill's allowed set.
  - `extract_section`: General-purpose markdown section extractor (heading to next heading).
  - `yaml_block_scalar`: Extracts a top-level YAML scalar from a `signal_verdict` block.
  - `extract_yaml_blocks`: Extracts content between ```` ` ```yaml` fences.
  - `get_allowed_verdicts`: Parses backtick-quoted values from `Allowed verdicts:` line.
  - `scan_skills`: Iterates `skills/*/SKILL.md` and runs the two skill-level checks.
  - All existing structural checks (frontmatter, enums, sentinels, idempotency keys) remain intact and pass.
  - `signal` (orchestrator) and `signal-task` gracefully skip checks for missing Output Contract / Allowed verdicts lines.
