## What

Create three new Phase 2 fixtures covering the campaign scope flow. Each fixture has a complete `.signal/` snapshot, an `expectations.md` with YAML frontmatter (`dispatch_skill`, `ignore_fields`, `max_attempts`), expected verdict, end expected mutations.

### `campaign-brief-to-plan`

Snapshot: task at `phase: plan` with approved `brief.md` (`scope: campaign`, channels: [linkedin, instagram], languages: [en]), `compliance.md` at `status: clear`, `.signal/context/` with brand.md and product.md.

Trigger: `signal` dispatches `signal-plan` for the first time.

Tests: `signal-plan` reads brief.md, generates `content-plan.md` with strategy summary, channel/language matrix, and asset plan table (2 assets: A1-linkedin-en, A2-instagram-en, both `asset_type: social-copy`). Creates matching `A<N>-*.md` stubs at the task root with full frontmatter (id, parent, title, status: todo, asset_type, channel, language, depends[], brand_version, product_version). Returns `awaiting-approval`.

Expected verdict:
```yaml
signal_verdict:
  verdict: awaiting-approval
  target: null
  summary: "Campaign plan and asset stubs are ready for approval."
```

Expected mutations: `content-plan.md` created with frontmatter and 6 required sections, 2 asset stub files created, stubs have `brand_version` and `product_version` pinned from context.

### `plan-review-reject-rework`

Snapshot: task at `phase: plan-review` with approved content-plan.md that has a deliberate flaw (missing Instagram channel coverage — brief says 2 channels but plan only lists 1). Assets all have correct frontmatter.

Trigger: `signal` dispatches `signal-plan-review` in a fresh sub-agent context.

Tests: `signal-plan-review` detects the coverage gap, writes `plan-review.md` with findings, returns `redirect target: plan`. `signal-plan` on re-dispatch fixes the missing channel, adds the stub, updates content-plan.md and `## Revision Notes`, marks old stale stubs as `status: cancelled` rather than deleting them. Returns `awaiting-approval`. User approves → `phase-complete`. Plan-review re-runs → passes.

Expected verdict (first run):
```yaml
signal_verdict:
  verdict: redirect
  target: plan
  summary: "Campaign plan review found fixable issues."
```

Expected mutations (first run): `plan-review.md` created with findings naming the missing channel. On re-plan: new stub created, obsolete stubs at `status: cancelled` with `cancelled_reason`, `content-plan.md` `## Revision Notes` updated.

### `campaign-multi-asset-create`

Snapshot: task at `phase: create` (campaign scope) with approved content-plan.md listing 3 assets (A1-linkedin-en social-copy, A2-instagram-en social-copy, A3-email-en email-copy). A1 and A2 are `social-copy` (implemented worker). A3 is `email-copy` (Phase 3 worker — should be stamped correctly but blocked by signal-worker with "worker not yet implemented"). All stubs at `status: todo`, `review_ai_pass: null`.

Trigger: `signal` dispatches `signal-create` for the campaign path.

Tests: `signal-create` reads content-plan.md (not brief.md), builds eligible list (A1, A2 — both `status: todo`, no deps, a workers implemented). A3 is eligible but signal-worker blocks it (worker not implemented). A1 and A2 dispatched in parallel via `signal-worker`. Returns `phase-complete` if A1+A2 done, `awaiting-input` if A3 blocked.

Expected verdict:
```yaml
signal_verdict:
  verdict: phase-complete  # or awaiting-input if A3 blocks
  target: null
  summary: "Assets created."
```

Expected mutations: A1 and A2 `status: done` with generation_log populated, A3 `status: blocked` with completion note.

## Why

Phase 2 added `signal-plan` and `signal-plan-review` — two new phase skills in the campaign flow (`brief → plan → plan-review → create → review → publish → done`). The existing 7 fixtures only cover quick scope and orchestrator routing. Campaign fixtures test the new skills, the plan-review rework loop, the campaign create code path, and the cancelled-stub lifecycle.
