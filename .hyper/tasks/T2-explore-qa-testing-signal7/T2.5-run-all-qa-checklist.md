## What

Two artifacts in one slice — both are consumer-facing and independently verifiable.

### `scripts/run-all-fixtures.sh`

Walks all 7 fixture directories under `evals/signal-fixtures/` and replays each via `replay-fixture.sh`, collecting results into an aggregate report.

Behavior:
1. Scan `evals/signal-fixtures/*/` for directories containing `expectations.md`.
2. For each fixture, invoke `replay-fixture.sh <fixture-name>`.
3. Collect each fixture's pass/fail/error status.
4. Print a summary table at the end:
   ```
   Fixture                         Verdict  Mutations  Attempts  Status
   quick-social-happy              PASS     PASS       1         PASS
   review-rejection-rework         PASS     PASS       2         PASS
   ...
   ```
5. Exit 0 if all fixtures pass, 1 if any fixture fails, 2 if any fixture has an execution error.

Runs fixtures sequentially (not in parallel) to avoid temp directory collisions and LLM rate limits.

### `evals/qa-checklist.md`

A human-readable markdown checklist for pre-ship manual verification:

1. **Bootstrap from scratch.** Run `/signal` on an empty project. Verify `.signal/` directory is created, brand.md and product.md are copied to context/, config.yaml exists.
2. **Quick-scope happy path.** Run `/signal Write a LinkedIn post about our Q1 results`. Walk through brief → create → review → publish. Verify all artifacts exist, no `<TODO>` sentinels, verdict transitions correct.
3. **Review rejection rework.** At the review approval gate, reply `reject: too casual`. Verify asset flips to `needs-revision`, review.md records the rejection, orchestrator redirects to create.
4. **Campaign Phase 2 refusal.** Run `/signal Create a campaign for Instagram + LinkedIn`. Verify signal-brief refuses with clear "Phase 2 not yet implemented" message.
5. **Duplicate publish.** After a successful publish, re-run publish. Verify publish-log.md records `skipped-duplicate` with the same idempotency key, no new `published` entry.

Each step lists the expected commands/skills and the artifacts to check.

AC 6, AC 8 — `run-all-fixtures.sh` makes replaying all fixtures a single command. The QA checklist is the human-facing Layer 3 from the exploration. Both are low-effort artifacts that complete the three-layer strategy.
