## What

Write the core Layer 2 script: `scripts/replay-fixture.sh`. This is one vertical slice that includes verdict extraction, comparison, mutation diffing, retry logic, and lenient/strict mode — everything the harness does in a single replay pass.

Signature:
```bash
./scripts/replay-fixture.sh <fixture-name> [--host claude] [--strict]
```

Behavior:
1. Read `dispatch_skill:`, `ignore_fields:`, `max_attempts:` from the fixture's `expectations.md` YAML frontmatter.
2. Validate that `dispatch_skill:` maps to an existing skill folder under `skills/`. Exit 2 if not.
3. Create a temp directory. Copy the fixture's `.signal/` into it as the working project state.
4. Invoke the skill via the host's sub-agent mechanism. On Claude Code, use the Task tool with `subagent_type: general-purpose`, pointing the working directory at the temp `.signal/`. Pass the trigger message from `expectations.md` as the dispatch prompt.
5. Capture the full sub-agent output.
6. Extract the final fenced YAML `signal_verdict` block (use the *last* fenced YAML block in the output, per the contract that verdict comes at the end). If no block is found, exit 2.
7. Parse the verdict YAML. Handle whitespace drift, trailing newlines, inconsistent indentation gracefully.
8. Compare verdict:
   - **Lenient (default):** `verdict` exact match, `target` exact match, `summary` contains key terms from the expected summary (extract noun phrases and action verbs from expected summary, check each appears in actual). If verdict+target match but summary diverges, log a warning — pass the verdict check.
   - **Strict (--strict):** full YAML key-by-key exact match including `summary` text. Normalize whitespace before comparison.
9. Mutation diff: after verdict comparison, diff the post-replay `.signal/` state against the "Expected mutations" section in `expectations.md`.
   - For each expected mutation, verify the field exists and has the expected value.
   - Skip fields listed in `ignore_fields:` (default `[updated_at, timestamp, actual_publish_time]`). For these, check presence only (field exists, value is non-null).
   - Flag unexpected file changes or extra fields not in `ignore_fields:` as failures.
   - Check file creation/deletion (e.g., archive folder appears, dashboard regenerated).
10. Retry logic: if verdict comparison OR mutation diff fails, retry up to `max_attempts:` total (default 3). Host-level errors (exit 2 causes: model timeout, skill not found, no verdict block, sub-agent crash) do NOT count against the retry budget — they are infrastructure failures, not behavioral failures.
11. Exit: 0 if any single attempt passes (verdict + mutations both match), 1 if all attempts fail on behavioral mismatch, 2 on execution error (host unavailable, missing skill, no verdict block).
12. Cleanup: remove the temp directory on exit regardless of result. On crash (SIGINT, SIGTERM), attempt cleanup before exiting.

## Why

AC 3, AC 4, AC 5, AC 10 — the harness is the core deliverable. It turns every fixture's static expectations into an executable test. Mutation diffing belongs in the same slice because it's part of "does this replay pass?" — splitting it into a separate subtask is horizontal decomposition with no independent verification path.

## Done when

- `./scripts/replay-fixture.sh quick-social-happy` exits 0 on a correct Claude Code replay.
- Intentionally wrong verdict YAML in a fixture causes exit 1.
- Missing `dispatch_skill:` in expectations.md causes exit 2.
- `--strict` flag triggers exact summary match; without it, lenient mode passes on verdict+target match even with divergent summary.
- `ignore_fields:` are skipped during mutation diff; non-ignored field mismatches are flagged.
- Third retry that passes marks the fixture as pass; all 3 failures mark it as fail.
- Temp directory is cleaned up after each replay regardless of result.
